# Tech Stack and Library Usage Rules

- **Framework**: React 18 with TypeScript
- **Routing**: React Router v6 (keep all route definitions in `src/App.tsx`)
- **Styling**: Tailwind CSS – use utility classes for layout, spacing, colors, and responsive design
- **UI Components**: shadcn/ui library (built on Radix UI and Tailwind) – use prebuilt components; do not modify them directly, create new components if customization is needed
- **Icons**: lucide-react – import icons as needed
- **State Management**: Prefer React hooks (`useState`, `useEffect`, `useContext`); only introduce external state libraries (e.g., Zustand, Jotai) if justified by complex global state
- **Form Handling**: Use React Hook Form or shadcn/ui form components; avoid manual form state unless trivial
- **Data Fetching**: Use React Query or SWR for server state; avoid raw `fetch` in components for complex caching needs
- **Testing**: Vitest for unit tests; React Testing Library for component tests
- **Code Quality**: ESLint with Prettier formatting; enforce TypeScript strict mode

## Library Usage Rules

- **Do not** install additional UI libraries (e.g., Material-UI, Ant Design) – rely on shadcn/ui and Tailwind.
- **Do not** write custom CSS or CSS-in-JS; use Tailwind classes exclusively.
- **Do not** modify files inside `src/components/` that are generated by shadcn/ui; instead, create new components in `src/components/` for custom UI.
- **Do** import icons from `lucide-react` and use the `LucideIcon` type for TypeScript safety.
- **Do** keep routing centralized in `src/App.tsx`; avoid scattering route definitions.
- **Do** use React Query/SWR for data fetching logic; keep fetching hooks in `src/hooks/` or alongside components.
- **Do** follow the existing folder structure: pages in `src/pages/`, components in `src/components/`, hooks in `src/hooks/`, utils in `src/utils/`.
- **Do** ensure all new components are exported and used in the appropriate page (typically `src/pages/Index.tsx` or other page files) so they appear in the UI.
